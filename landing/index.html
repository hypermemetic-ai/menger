01 — the problem

Plans drift away from the work.

Three ways a plan stops being true, and what menger does about each.

01.1

The plan lives in one place, the work in another.

The plan is a document or a board from last month. What is really being built lives in branches, chat and someone's head.

01.2

Status is whatever someone last typed.

A ticket says “in progress” for three weeks. Is it blocked, finished, or forgotten? You find out by asking.

01.3

People and agents work blind to each other.

An agent starts work a teammate already claimed. A teammate waits on a question an agent asked in a log nobody read.

02 — how it works

Write the plan. Promote what's ready. Watch it land.

Scroll: one ticket, OFFLINE-10, moves through the three steps on the right.

step 01

Write the plan as a tree.

Start with a scope: the goal. Break it into builds, spikes, fixes and rollouts, and say what waits on what. Every piece is Pending until you say otherwise.

step 02

Promote what's ready.

You move a ticket to Ready. Whoever starts it — a teammate or an agent — marks it Coding, so nothing is picked up twice.

step 03

Watch it land.

Each commit links to the ticket it finishes. Review and merge move it to Complete, and every board and page shows it at once.

04 — six principles

menger has opinions about how a plan should behave.

Each one is something you can see in the app.

01

A plan is a tree.

Scopes break into work, and work breaks down until each piece fits one person or one agent. What a piece produces — a spike's answer, a benchmark, a report — is filed beneath it, so every result shows where it came from.

Learn more about tickets and kinds
02

Status is a contract.

Each status means one thing and has one owner: people promote Pending to Ready, a worker sets Coding the moment they start and In Review when the work is committed, and whoever merges marks it Complete. So when the board says Coding, someone really is.

Learn more about the lifecycle
03

Everything is live.

Every screen holds one open connection, and the server pushes each change down it as it happens: nothing polls, nothing waits for a refresh. Everyone looking at the plan sees the same plan.

Learn more about the board
04

One wire for people, scripts and agents.

Everything menger does is a method on one Plexus RPC connection, and the app has no private side door. The web app, the synapse command line and your agents make the same calls, so anything you can click, a script can do.

Learn more about the command line
05

Decisions live inside the work.

When a ticket needs a call, it asks the owner right there: one choice, several, or a written reply, with each option's cost and a recommendation. The answer is kept with its history, next to the work that depends on it.

Learn more about inputs
06

Yours to run.

Use the hosted app, the desktop app — on its own or connected to a server — or one binary on your own machine with a SQLite file. menger is open source under the MIT licence, so you can always run it yourself.

Learn more about running your own

How to run it
Which file to download, and the first-open warning

Linux

  • AppImage — most distributions: chmod +x menger_*_amd64.AppImage, then run it
  • .deb — Debian, Ubuntu
  • .rpm — Fedora, openSUSE
Linux builds

macOS

  • Apple Silicon — menger_*_aarch64.dmg
  • Intel — menger_*_x64.dmg

First open: macOS says the developer cannot be verified. Control-click the app, choose Open, then Open again (or System Settings → Privacy & Security → Open Anyway).

macOS builds

Windows

  • Installer — menger_*_x64-setup.exe
  • MSI — menger_*_x64_en-US.msi, for managed installs

First run: SmartScreen says it protected your PC. Choose More info, then Run anyway.

Windows builds

The builds are signed for the self-updater, not yet by Apple or Microsoft — hence the warning on first open. Mobile apps are coming.
