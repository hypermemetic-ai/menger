1

What it is

menger is a ticket tracker for plans made of many pieces — written by people, carried out by people and agents. Every ticket lives in a shortcode: MENGER-7 is the seventh ticket of MENGER. A shortcode begins with a scope (or a doc) as its root, and shortcodes nest under one another, so a whole organisation's work is one tree — the house tracker has three roots: MENGER, PLEXUS and OUGHT.

Every ticket has a kind:

  • scope decomposes into children — the branches of the plan.
  • build produces a capability.
  • execution carries out a procedure.
  • gap a defect in shipped behaviour.
  • spike answers a question.
  • doc not work: a finding, a manifest, a reference. It has no lifecycle.

A ticket's outputs are tickets. A report, a spike's answer or a checkpoint is filed as a child of the ticket that produced it, so the tree shows where every result came from. Bodies are markdown, and may hold diagrams, HTML and live components.

2

Signing in

  1. Press Log in. You land on menger's own sign-in page.
  2. Choose how. Type your email and receive a code, or continue with Google, GitHub or Apple. A company email goes straight to your company's single sign-on, by its domain. If you have turned on an authenticator app, it asks for that code too.
  3. Wait for a role, the first time. Signing in proves who you are; menger's own members decide what you see. Until an admin grants you a role you reach nothing, and you are listed as waiting on the admin's #/members page.
Roles, each held on a shortcode (and everything under it) or on everything
RoleMay
viewerread under the scope, and comment
editoralso create and change tickets, and answer inputs
adminalso grant and revoke roles on the scope

A sign-in lasts 12 hours by default. Signing out ends the session, and its open tabs stop answering.

3

The board and a ticket

The app opens on the board: every ticket you can read, one line each, beside the nav — the tree of shortcodes, each with its done/total. Open a ticket for its page: its status, kind, parent, blockers, body, children and the commits that finished it. Another window's change appears on yours as it happens.

The lifecycle

  1. PendingWritten down, not yet approved. Work does not start on it; a person promotes it.
  2. ReadyApproved. It can start once everything it waits on is done.
  3. CodingSomeone has started — set the moment work begins, so nothing is claimed twice.
  4. In ReviewThe work is finished and committed, and waits to be merged.
  5. CompleteMerged. Done.

Beside the line: Superseded replaced by another ticket · Canceled will not be done · Blocked a marker · Idea parked · Epic a scope's status · Doc a doc's only status.

What waits on what

A ticket names the tickets it is blocked by. A blocker is satisfied when it is Complete, Superseded or Canceled. The ready set is every Ready ticket whose blockers are all satisfied — what can start now. The wave board (#/waves/<SHORTCODE>) lays a shortcode's work out in order: wave 1 can start now, wave 2 once wave 1's blockers land, and so on — and moves the cards as the work moves.

4

Finding things

Filters reach every view. The header's Filter button (F) filters everything; each view — board, wave board, nav, inputs — has its own (f). Pick categories from the menu, or type the filter language:

  • ready and kind build workable builds
  • status in (Pending, Ready) not started
  • category in (active, review) in flight
  • not category done everything open
  • under MENGER-2 a ticket and everything below it
  • ready and kind build and in SCALE combined

A filter rides the page's address, so a link restores it; Saved ▾ keeps one under a name for everyone. Right-click any tag — a shortcode, a status, a kind — to filter by it.

Search looks inside titles and bodies: every word required, prefixes and typos forgiven, best match first. The palette (/ or Ctrl+K, ⌘K on a Mac) jumps to a ticket by id or title and shows the passages that match below.

5

Inputs: questions asked inside a ticket

A ticket can ask its owner something and keep the answer: a decision (pick one), a multi (tick any) or a text reply. You answer in the ticket's own page; every answer is kept with its history. Agents ask; the owner answers.

Expired events: archive or delete?

  • Archive cost: a second store · holds honoured recommended
  • Delete cost: holds broken · nothing to run

Whoever asked acts on the answer and then closes the input, which freezes it: DECIDED. #/inputs lists everything waiting on you across every ticket; once you have opened it, the header counts what is still open. Answering needs the editor role.

6

Comments and notes

Comments are a reader's notes on the app itself. Press a (or Annotate in the header): every element is outlined — inside ticket bodies too — and a click opens a comment box right there. Numbered pins mark what has open comments, each with Resolve. #/comments lists them all, each linking back to its spot; a ticket's page counts its open ones.

Notes are thoughts written down before they are tickets: dated, untitled, on no shortcode. When one is ready, upgrade it and it becomes a ticket, its text the body.

7

From the command line

Everything menger does is a Plexus RPC method — there is no side door, so the app, scripts and agents use the same calls. synapse is the CLI over any Plexus backend. It speaks WebSocket to a server's port: point it at your own server (port 4455 by default). Parameters are flags; <method> --help lists them.

synapse -P 4455 menger tickets health
synapse -P 4455 menger tickets list --filter 'blocked' --summary true --limit 20
synapse -P 4455 menger tickets ready_set --filter 'kind build' --summary true
synapse -P 4455 menger tickets search --query 'placement wave'
synapse -P 4455 menger tickets get --id MENGER-7
synapse -P 4455 menger tickets watch                     # every change, live
synapse -P 4455 menger tickets create --epic HOME --kind scope --title 'Home'
synapse -P 4455 menger tickets create --epic HOME --title 'Fix the gate' --kind build
synapse -P 4455 menger tickets set_status --id HOME-2 --status Ready
synapse -P 4455 menger tickets link_commits --id HOME-2 --commits 77df9a0
synapse -P 4455 menger tickets inputs --state open
synapse -P 4455 menger tickets answer --ticket HOME-3 --input landing \
  --value.type choice --value.option archive --rationale 'holds are real'
synapse -P 4455 menger comments list --state open
synapse -P 4455 menger notes add --body 'the palette should remember its last query'
synapse -P 4455 menger notes upgrade --id 1 --epic HOME

The first ticket of a shortcode must be a scope or a doc. Global options (-P, -j for JSON) go before menger.

8

Desktop app

menger for your desktop opens on a choice: Local — your tickets on this computer, a menger running inside the app, nothing leaving the machine — or Remote, a menger server at an address you give (such as https://app.menger.sh). Once installed, it updates itself: it checks for a new version when it starts, and asks before installing.

9

Run your own

menger is one binary with the web app built in and a SQLite file as its system of record. With Rust installed:

cargo install menger --features embedded-app
menger --db-path ~/menger/tickets.db
# the app       http://127.0.0.1:4456/
# WebSocket     ws://127.0.0.1:4455   (synapse -P 4455 …)
# REST + SSE    http://127.0.0.1:4457 (--no-rest turns it off)

Other ports: --port (WebSocket), --shell-port (the app), --rest-port. Open the app in two windows, change a status in one, and watch the other follow. With no --auth-provider there is no login — everyone on the machine is everyone; menger --help lists the sign-in flags (--auth-provider, --require-login, --admin, --public-url). Before a deploy, menger --verify-derived --db-path … checks the file.
